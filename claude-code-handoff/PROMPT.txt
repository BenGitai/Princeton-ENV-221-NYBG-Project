CLAUDE CODE PROMPT: NYBG "Garden Escapes" invasive species guide (build v1, from mockup v3)
=================================================================================

HOW TO USE: open Claude Code in the "NY Botanical Gardens" folder and paste everything below the line.

----------------------------------------------------------------------------------------------

Build the website shown in the mockup in claude-code-handoff/design-reference/: exactly that design and behavior, as a real, local, offline website.

## 1. What it is

A mobile-first website, which also works well on desktop, that guides visitors to the New York Botanical Garden (NYBG) through its invasive species. It is a student capstone prototype for ENV 221 (Princeton), done with Dr. Evelyn Beaury, NYBG Center for Conservation & Restoration Ecology.

- It must run locally and offline: double-clicking nybg-guide/index.html must work. No backend, no accounts, no install needed just to view it.
- Build the site in a new folder, nybg-guide/. Everything outside nybg-guide/, guide-build-kit/ and claude-code-handoff/ is read-only source material.

## 2. Non-negotiable: species content is copied from sources, never written by AI

- Every species fact comes from the extraction pipeline in guide-build-kit/, which copies text word for word from the source files and tags where each piece came from. Never write, paraphrase, summarize or "improve" species text, including teasers. Where a short teaser is needed, use the first sentence of a sourced field.
- Every content section on a species page ends with "Source: …".
- Where something is missing, show a visible bracketed placeholder (dashed box) that names the file which would fill it.
- UI labels and button text are the only text you may write.

## 4. Architecture (modular: each concern changes in exactly one place)

Plain HTML, CSS and vanilla JS. No framework, and no bundler needed to view the site. It must work from file://, so no fetch() of local files and no ES modules: use classic <script> tags that register onto window.NYBG.

1. Data bundle: tools/bundle_site_data.py (add it as the last step of build_data.py) writes nybg-guide/data/guide-data.js (`NYBG.data = {species, webs, shared_nodes, tour, links, assets}`) and copies photos and SVGs into nybg-guide/assets/.
2. Store (js/store.js): the only code that reads NYBG.data. API: species(id), search(q, filter), stops(), stop(n), stopForSpecies(id), web(id), webLinks(id), photo(file), links().
3. Config: js/config/species-page.js is an ordered SECTION REGISTRY of { id, title, when(sp), render(sp), source(sp) }. js/config/nav.js is the one list behind both the top bar and the tab bar (as in NavBar.dc.html). js/config/home.js holds the home tiles.
4. Components (js/components/): navBar, chip, card, bottomSheet, sourceLine, placeholder, checklist, nativeGrid, inatLink, provenanceList, readAloud, webView (SVG drawn at runtime), mapView.
5. Screens (js/screens/): home, map, stop, species, lookup, layers, quest, hub. Each exports render(params) and only composes components and store calls.
6. Router (js/router.js): hash routes #/ · #/map · #/map/N · #/stop/N · #/species/<id> · #/lookup?q=&filter= · #/layers/<id> · #/quest · #/hub. Back and forward must work.
7. Theme (css/tokens.css): every color, font, radius and spacing value as a CSS variable, taken from the mockup.
8. State (js/state.js): quest progress, checklist ticks and the read-aloud setting in localStorage, every access wrapped in try/catch.

## 5. Responsive rule: layout depends on the space available, not on which screen it is

- Each screen is one component that adapts by width, using CSS container queries on its root (container-type: inline-size), exactly as in the mockup's <helmet> CSS.
- At 900px and up, screens use the top nav (the tab bar hides), wider padding and multi-column layouts:
  Home: hero text beside a large map card, tiles in 4 columns, month card beside the read-aloud setting.
  Map: map on the left, stop page in a 480px panel on the right; clicking a pin updates the panel in place.
  Lookup: results list (420px) on the left, the selected species page on the right.
  Forest layers: web at 1.2x scale on the left, node card (400px) on the right.
  Quest and Take it home: two columns.
- The species page has its own container query at 760px: hero and header side by side, then text sections on the left and checklist, natives, layers, iNaturalist and provenance on the right. Because it queries its own width, it stays single-column inside the 480px map panel even on a desktop screen.
- Below 900px: one column with the bottom tab bar (Home, Map, Species, Quest, At home). Forest layers has no tab bar on phones.
- Test at 360x740, 390x844, 768x1024, 1024x768 and 1440x900. No horizontal scrolling at any size.

## 6. Screens (match design-reference exactly)

Palette: ink #1F2D1C, ink-soft #4A5942, paper #F4F6EE, paper-2 #E6ECDA, rule #CCD5BE, forest #23402B, moss #2F6E45, invader #C21E5A (banner #FCE3EC / #8E1442), help #B9770F, natives panel #E3EEF7. Fonts: Alegreya (display) and Alegreya Sans (body) via Google Fonts, falling back to Georgia / system-ui offline. Touch targets at least 44px, no emoji.

- Home (Main.dc.html): hero, "Look up any invasive species", "Your walk" (4 stages from tour.json), 4 tiles, a "Look for it this month" card picked from species seasons data for the current month (with its source line), and the setting "Read each stop aloud when I arrive".
- Map (Tour.dc.html): the illustrated map, dashed route and numbered pins from tour.json (pink = species stop, green = place stop). Stage chips dim the other stages' pins. Tapping a number opens a bottom sheet: number, stage, name, place, photo, a first-sentence teaser, prev/next arrows, "Open stop N". Pinch-zoom and pan on phones with pins at constant size, plus a "List view" toggle. Place stops (1 and 10) show the intro quotes or the native swaps from tour.json, with their sources.
- Species page (SpeciesPage.dc.html), sections in registry order, each shown only when its data exists:
  hero photo or placeholder; place line on tour stops (+ "Spot to confirm" if verify); name, scientific name, family, "Also called"; pink status banner with native range; badges (NYBG Category, NY State regulated if the list sources include NYS 575, LH PRISM priority, first record at the Garden); READ-ALOUD player; What it is; Why it matters; Below the surface; Threat to the Thain Forest; At the Garden; How NYBG manages it; Spot-it checklist (tickable, "N of M", a "Right now (Month)" callout, and at 3+ ticks "add it to my Quest"); Plant these instead; Forest layers card (tour species only) -> #/layers/<id>; ONE iNaturalist link; "This page was built from" provenance list.
- Species lookup (Lookup.dc.html): search over common names, scientific names and synonyms for all 420 species; filters All / On the tour / Has a full page / Category 1 / Category 2 / Pests & diseases; tags; source dots; 40 results then "Show more"; selecting a row opens #/species/<id> (on desktop, in the right pane).
- Forest layers (Layers.dc.html): exists ONLY for the 8 tour species, one web each, all from build/webs.json. A chip row switches between them. Draw the web as SVG over forest-layers-bg.svg: node rings colored by group, with harms (solid pink), helps (dashed amber), partners (dotted green) and "named together" (dashed grey) arrows. The node card shows the verbatim quote and source, plus link buttons: "Species page" (#/species/<id> for nodes with a species), "Its own web" (when that species has a web), and "Also in: <web>" for each other web sharing the node's shared id. Nodes that link out get a small arrow badge.
- Garden Escape Quest (Quest.dc.html): the list comes from tour.json's species stops; progress bar; Spot it / Found toggles saved in localStorage; ONE iNaturalist button (the project link from links.json); a "Visitor impact" placeholder.
- Take it home (HomeHub.dc.html): ZIP search with placeholder nurseries from data/nurseries.js; native swaps from tour.json (photos found by name in the info-page data) with their source; regional links from links.json.

## 7. iNaturalist: one link, no lists

- Species page: a single "See it on iNaturalist" link built from links.json species_url_template (the species' sightings inside the Garden, place_id 66109), plus a static record count when the sources have one.
- Quest: a single "Log a sighting on iNaturalist" button to the project in links.json.
- Nowhere else. Optional: when online, fetch a live count from https://api.inaturalist.org/v1/observations?place_id=66109&taxon_name=<sci>&verifiable=true&per_page=0, without ever blocking rendering.

## 8. Read-aloud: reads out the page, nothing more and nothing less

- Use the browser's Web Speech API (speechSynthesis). No recorded audio, no extra narration, no intros, no summaries.
- The text spoken is exactly the visible content text of the current page, in on-screen order: titles, labels, paragraphs, list and checklist items, captions, quotes, swaps and "Source:" lines. Implement this by marking content elements with data-read and reading their textContent in DOM order, so speech can never drift from the page. Do not read controls (buttons, nav, the player itself) and do not read hidden elements.
- Player: play, pause/resume, stop, and "Reading part N of M" progress. Highlight the element being read and scroll it into view; respect prefers-reduced-motion.
- Speech stops when the page changes. If the home setting "Read each stop aloud when I arrive" is on, start reading when a stop page opens.
- If speechSynthesis is missing, show "Read-aloud is not supported in this browser".
- Every page with content gets the player: species pages and the place stops (1 and 10).

## 9. Accessibility

Pins, web nodes, checklist items and toggles are real <button>s with labels. Bottom sheets are focus-managed and close on Escape. Every image has alt text, and webs also get a text list of their arrows. Text contrast is at least 4.5:1. Visible focus rings. Respect prefers-reduced-motion.
