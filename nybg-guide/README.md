# Garden Escapes: NYBG invasive species guide

A mobile-first website that guides visitors to the New York Botanical Garden through its invasive
species. Student capstone prototype for ENV 221 (Princeton), with Dr. Evelyn Beaury, NYBG Center for
Conservation & Restoration Ecology.

Every species fact on the site is copied word for word from a source file by the scripts in
`guide-build-kit/`, and every content section names its source. Nothing in `nybg-guide/` contains
hand-written species text. The project's own sources come first (the published Forest Plan, ENV 221 info
pages, cascade pages). Where they are silent, gaps are filled from public-domain U.S. government
publications and openly licensed photos, each cited on the page. Where nothing is available, the page
shows a dashed `[placeholder]` that names the file that would fill it.

## Open the site

Double-click `nybg-guide/index.html`. It runs offline from your computer in Chrome, Edge, Firefox
and Safari, with no install and no server. When you're online it also loads the Alegreya fonts and a
live iNaturalist record count; offline it falls back to Georgia / system fonts and the record count
from the sources.

Pages you can link to directly (add these after `index.html`):

| Link | Page |
|---|---|
| `#/` | Home (landing page: the hunt, a live map, "Why it matters") |
| `#/map`, `#/map/4` | Garden map (with stop 4 previewed) |
| `#/stop/4` | Stop 4 (phones: the stop page; wide screens: map + stop side by side) |
| `#/species/alliaria-petiolata` | Any species page (ids are in `guide-build-kit/build/species.json`) |
| `#/lookup?q=knotweed&filter=tour` | Species lookup (filters: `all`, `tour`, `full`, `c1`, `c2`, `pests`) |
| `#/layers/reynoutria-japonica` | Forest layers for a tour species |
| `#/quest` | Garden Escape Quest |
| `#/hub` | Take it home |

`debug.html` prints what the data store returns, which helps when checking a content change.

## Update the content

Never edit `guide-build-kit/build/` or `nybg-guide/data/guide-data.js` by hand: they are regenerated.
Change a source or a `guide-build-kit/content/` file, then rerun the pipeline from the
`NY Botanical Gardens` folder:

```
python guide-build-kit/tools/build_data.py
```

It should end with `site data: 40 species, 8 webs, … -> nybg-guide/data/guide-data.js`, then
refresh the browser.

### What is published

Everything in `nybg-guide/` and `guide-build-kit/` is public. It holds facts and published text only:

- **NYBG's 2026 invasive species list:** the facts in its species tab (scientific names, synonyms,
  common names, Category 1/2, and the public lists that name each species). The workbook itself is not
  in the repository, and neither is its staff guidance (the Read Me tab on handling specimens in the
  living collections), the draft invasive species policy, or the methods guide. None of them are quoted
  anywhere.
- **Published text:** the Forest Plan (published by NYBG), the ENV 221 student pages, NYBG staff quoted
  from published web pages, and public-domain U.S. government publications.
- **Photos:** only openly licensed ones. `build_species.py` drops any info-page photo whose credit
  doesn't name an open license (or says "credit to confirm"). Native-plant photos are replaced by the
  Wikimedia Commons photos in `content/public-sources.json` (`plant_photos`), each credited on the page.
  The original deck and Reference Guide images stay on your computer (`guide-build-kit/photos/` is not
  committed, except `photos/public/`).

- **New info-page slide** (photo, native range, "Why it matters", "Plant these instead"): add the slide
  to the ENV 221 info-page deck (any `*Info Page*.pptx` in the `NY Botanical Gardens` folder, or a
  deck in `guide-build-kit/content/info-pages/`) and rerun.
- **New spot-it checklist** for a species without a cascade page: add it, copied word for word with
  its source, to `guide-build-kit/content/id-checklists.json`, then rerun. Format:
  `"<species-id>": {"source": "...", "items": ["..."], "seasons": [{"months": [4, 5], "look": "..."}]}`.
  `seasons` also feeds the "Right now" note on the page and "Look for it this month" on Home.
- **NYBG staff in their own words** ("From NYBG staff" on the species page): add a short passage, copied
  word for word from a published page, to `guide-build-kit/content/nybg-voices.json` with the page's
  author, title, date and link, then rerun. Each passage can have a title, a few sentences (`text`), one
  pull quote (`quote`) and who said it (`speaker`). A species listed only there still gets a page.
- **New forest-layers rule**: add a rule to `guide-build-kit/content/web-rules.json` (regex → node,
  word-for-word quote, arrow label) and rerun. Every tour species gets a web generated by
  `make_webs.py`; nobody draws webs by hand.
- **New or moved tour stop**: edit `guide-build-kit/content/tour.json` (number, stage, place, map x/y,
  species id, `verify`) and rerun. Pins, the dashed route, the Quest list, stop pages and forest-layers
  webs all follow from it. If the route between two stops should curve, give the later stop a
  `route_in` with SVG path commands (see stop 10).
- **New cascade page**: drop `<name>-cascade.html` in the `NY Botanical Gardens` folder and rerun.
- **Public sources** (gap-filling): `guide-build-kit/content/public-sources.json` lists, per species and
  field, a document in `guide-build-kit/sources/public/`, its pages and a short start and end phrase;
  `extract_public_sources.py` copies the text between them word for word, and the build stops if a phrase
  is not found. Only U.S. government works (public domain) are used for text. Photos are Wikimedia
  Commons files named there; `fetch_public_photos.py` downloads any that are missing and records the
  author and license, which become the credit line. The sources used so far:
  - Swearingen et al. 2010, *Plant Invaders of Mid-Atlantic Natural Areas*, 4th ed. (National Park
    Service & U.S. Fish and Wildlife Service)
  - USDA Forest Service 2005, *Pest Alert: Hemlock Woolly Adelgid* (NA-PR-09-05)
  - Martin & McIntire, USDA Forest Service 2024, *Pest Alert: Beech Leaf Disease* (R9-PR-001-21, revised
    May 2024). Its file is a `.txt` transcription of the passages used, because the PDF could not be
    downloaded where the entry was built; dropping the PDF in and setting the source `type` to `pdf` replaces it.
  - Stone 2009, *Iris pseudacorus*, Fire Effects Information System (USDA Forest Service)
- **Species no project source covers** (for example beech leaf disease, found after the 2016 Forest Plan):
  give its entry in `public-sources.json` an `add` block (`scientific_name`, `common_names`, `kind`) and it
  gets a page built from public sources only.
- **Nurseries** ("Take it home" ZIP search): still placeholders in `nybg-guide/data/nurseries.js`.
- **"Why it matters" on Home**: `guide-build-kit/content/landing.json`. Each card is a quote copied word for
  word from an NYBG page or guide, with its source and link. Change the file and rerun.
- **Scavenger hunt**: there is nothing to edit. Every species stop in `tour.json` becomes a "wanted" card on
  Home and a pin to find on the map. "I found it" on the map, "Found" on the Quest and the cards on Home
  share one saved list in the visitor's browser.
- **iNaturalist links**: `guide-build-kit/content/links.json` (one place id, one species URL template,
  one project link).

### Windows notes

- `build_data.py` re-runs itself in UTF-8 mode, because Windows Python reads files as cp1252 by default.
- The Forest Plan extractor needs poppler's `pdftotext`. The copy Git for Windows puts on PATH is
  xpdf and doesn't work. The script finds a poppler one on PATH by itself (MiKTeX ships one).

## How the site is built

Plain HTML, CSS and JavaScript. No framework and no build step. Classic `<script>` tags register on
`window.NYBG`, so the site works from `file://`.

```
index.html              loads everything in order
data/guide-data.js      NYBG.data = {species, webs, shared_nodes, tour, links, assets}  (generated)
data/nurseries.js       placeholder nurseries
assets/                 photos, garden-map.svg, forest-layers-bg.svg (copied by the pipeline)
css/tokens.css          every color, font, radius and spacing value
css/base.css            reset, app shell, focus rings, reduced motion
css/components.css      one block per component
css/screens.css         one block per screen; container queries at 900px (screens) and 760px (species page)
js/ns.js                namespace, DOM helpers, icons
js/state.js             localStorage: quest progress, checklist ticks, read-aloud setting (all in try/catch)
js/store.js             the only code that reads NYBG.data
js/router.js            hash routes; back/forward; stops speech on every page change
js/config/nav.js        the one list behind the top bar and the tab bar
js/config/home.js       home tiles
js/config/species-page.js  the species page SECTION REGISTRY (add an entry -> it appears on every page)
js/components/          navBar chip card bottomSheet sourceLine placeholder checklist nativeGrid
                        inatLink provenanceList readAloud webView mapView
js/screens/             home map stop species lookup layers quest hub
```

**Layout by width, not by device.** Each screen is a CSS container. At 900px and up it uses the top
bar and multi-column layouts (map + 480px stop panel, lookup list + page, web + node card). The
species page queries its own width (760px), so inside the 480px map panel it stays one column.

**Read-aloud** reads the `textContent` of the visible elements marked `data-read` on the current
page, in on-screen order, with the browser's speech engine. So it can never say anything that isn't
on the page. Only the information is marked: names, status, headings, paragraphs, checklist items,
quotes, natives and swaps. Source lines, photo credits, subtitles, placeholders, links and controls are
not marked, so they are never read. Speech stops when the page changes.

## Publishing

The repository root (the `NY Botanical Gardens` folder) has a `.gitignore` that only lets `nybg-guide/`,
`guide-build-kit/` and `claude-code-handoff/` into git, so the raw source files stay local.
`.github/workflows/pages.yml` publishes `nybg-guide/` to GitHub Pages on every push to `main`
(one-time setting: Settings > Pages > Source: GitHub Actions). The site works from any static host
because it uses no server and no `fetch()` of local files.
